# Wktbox Branding and v0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the complete Wktbox logo package, render it in the README, remove the source ZIP, and publish the verified repository as v0.3.0.

**Architecture:** Documentation-owned branding lives under `docs/assets/branding`, while the README selects light and dark SVG variants with a `picture` element. The existing tag-triggered GitHub Actions workflow remains the sole publisher of release archives and runtime images.

**Tech Stack:** Markdown, SVG/PNG, Go documentation tests, Git, GitHub Actions, Docker.

## Global Constraints

- Publish version `v0.3.0` from the reviewed `main` commit.
- Retain all eleven image files from `WKTBox-logo-package (1).zip`.
- Rename `README-logo.md` to `docs/assets/branding/README.md`.
- Do not commit the source ZIP.
- Do not stage the unrelated `docs/superpowers/plans/2026-07-23-professional-release-agent-integration.md`.
- Use the existing release workflow; do not upload release assets manually.
